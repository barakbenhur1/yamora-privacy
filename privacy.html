Privacy Policy

Effective date: 9 September 2026
Operator: Barak Ben Hur, Israel
Privacy contact: yamora.privacy@gmail.com

Yamora is for adults aged 18 or older. Most persistent dating and learning data stays in the user's Chrome profile. Optional privacy-bounded model-improvement contribution begins only after explicit consent.

1. What Yamora does

Yamora is a local-first dating browser extension. It helps adults create a dating profile, discover mutually compatible people, express interest, form reciprocal matches, communicate privately, and improve compatibility ordering on the user's device.

2. Data processed and kept on the user's device

Yamora may locally process and store:

  • profile details, photos or other user-selected media, age, gender, relationship intent, preferences, and interests;
  • exact coordinates used to calculate distance locally, plus coarse location material used for peer discovery;
  • Interested and Pass choices, matches, compatibility state, conversation outcomes, and local learning state;
  • messages, reports, cryptographic identity material, encrypted-session metadata, and settings; and
  • features derived locally from pages for which the user granted optional website access.

Exact device latitude and longitude stay in Yamora's local profile state. When the user allows the optional city-name lookup, Yamora rounds the device location to an approximately 2 km grid and sends only that rounded point to BigDataCloud to obtain a human-readable city or area name. The exact device coordinates are not included in that request. BigDataCloud also necessarily receives normal network information such as the requesting IP address. The resulting city/area label is editable by the user.

Yamora does not request Chrome browsing-history permission. Raw page text, page titles, search text, and URLs used for current-page analysis are transient inference inputs and are not retained in Yamora's behavioral database. Users can control or remove optional website access and disable learning.

3. Peer and network processing

To provide discovery and communication, Yamora shares a bounded public dating profile, public profile media chosen by the user, reduced compatibility signals, coarse location or discovery material, and user-chosen communications with other Yamora peers. Peer application events, messages, and peer media use authenticated end-to-end encrypted sessions.

Relay and network providers necessarily process temporary connection information such as IP addresses while routing traffic. Yamora's signaling relay does not create a persistent database of profiles, exact locations, matches, or message contents. Connection metadata can also be visible to internet and infrastructure providers as necessary to deliver the service.

4. Optional pseudonymous model improvement

Contribution is off by default. Before it is enabled, Yamora presents an in-product disclosure describing the data and purpose and requires the user to take an affirmative consent action. If enabled, an installation may periodically send:

  • quantized, derived compatibility and reciprocal-feature values;
  • Interested/Pass, mutual-match, and bounded conversation-outcome labels;
  • bounded baseline and model prediction snapshots;
  • coarse day buckets and random pseudonymous installation, export, and example references; and
  • minimum-size aggregate age-band and gender quality cells used to evaluate model performance disparities.

These contributions exclude names, profile or candidate IDs, photos, audio, URLs, raw browsing or search text, exact coordinates, raw behavior vectors, message text, credentials, and payment information. The contributed data is used only to train, evaluate, secure, and improve Yamora's reciprocal matching functionality. It is not used for advertising, data brokerage, creditworthiness, or unrelated profiling.

5. Service providers and transfers

Yamora uses or may use the following service providers depending on which disclosed features are configured and enabled:

  • Render for the signaling relay. In production builds with optional model improvement enabled, Render may also host the training collector service;
  • MongoDB Atlas, when optional model improvement is enabled in production, for durable storage of explicitly consented model-improvement exports;
  • BigDataCloud for the optional client-side city/area lookup. Yamora sends a rounded approximately 2 km location point rather than the exact device coordinates; the provider also receives normal network information such as IP address as part of delivering the request;
  • GitHub Actions, when the automated model-improvement lifecycle is enabled, for ephemeral model training, evaluation, signing, and rollout; and
  • Google Chrome and the Chrome Web Store for extension execution and distribution.

If a user voluntarily opens Yamora's external support page, Ko-fi and its payment providers, which may include PayPal, process information the user provides directly to them under their own privacy policies. Yamora does not transmit dating-profile, browsing-derived, location, messaging, or model-improvement data to Ko-fi or PayPal.

These providers process data only as needed for the relevant disclosed function. Infrastructure may process data outside Israel, subject to the provider's contractual and security controls.

6. Voluntary support

Yamora may offer a link to Ko-fi where a user can voluntarily support the project. Contributions unlock nothing and do not affect ranking, visibility, matches, features, support priority, or data handling. Ko-fi and its payment providers process the transaction under their own terms and privacy policies. Yamora does not receive or store payment-card, bank-account, or payment-account credential information. Yamora stores only local support-prompt and link-open state and does not send that state to peers or the model-improvement collector.

7. Human access and disclosure

Yamora does not sell user data. User data is not used or transferred for personalized, retargeted, or interest-based advertising.

Humans do not read user data except when the user explicitly consents to human access to specific data for support, when access is necessary to investigate security or abuse, when required by applicable law, or when the information has been aggregated and anonymized for permitted internal operations. Information may also be disclosed when legally required or as part of a merger, acquisition, or sale of assets, subject to applicable law and continued protection.

8. Retention, consent withdrawal, and deletion

When optional production model improvement is enabled, accepted model-improvement export batches are retained for up to 730 days unless deleted earlier or longer retention is legally required. Users can pause future sharing or select Delete contributed copy inside Yamora. This deletes the installation's retained export batches, revokes its upload token, and clears its sharing consent. A deletion marker prevents later uploads from concealing that removal.

The next scheduled model lifecycle retrains without deleted contributions or retires the affected model if the remaining evidence is insufficient. Because the lifecycle runs daily and clients normally check for signed updates every six hours, a previously cached model may remain locally usable for approximately 30 hours after the server-side deletion process begins. Urgent requests can be sent to yamora.privacy@gmail.com.

Local data remains until the user removes it in Yamora, removes the relevant Chrome profile, or uninstalls the extension, subject to Chrome's behavior. Peer recipients retain communications on their own devices. Provider backups, security records, or legally required records may remain for the period required by provider operations or applicable law.

9. User choices and rights

Users can decline optional model contribution without losing access to Yamora's dating features. They can pause sharing and request deletion from within the extension when that feature is configured. For access, correction, deletion, objection, consent withdrawal, or another privacy request that cannot be completed in-product, contact yamora.privacy@gmail.com. The operator may request enough information to verify the request without collecting unnecessary identity data and will respond within the period required by applicable law.

10. Security

Yamora uses HTTPS and WSS for server transmission, authenticated encrypted peer sessions, strict server-side schemas, installation-bound collector credentials when model contribution is enabled, durable database controls for contributed data, signed and expiring model envelopes, staged rollout, monitoring, and automatic rollback where the corresponding production services are configured. No system can guarantee absolute security.

11. Children

Yamora is intended only for adults aged 18 or older. A person known or reasonably believed to be under 18 is not permitted to use Yamora. Suspected underage use can be reported to yamora.privacy@gmail.com; the operator will investigate and delete associated operator-controlled data where appropriate and legally permitted.

12. Chrome Web Store Limited Use

Yamora's use and transfer of information received from Google APIs complies with the Chrome Web Store User Data Policy, including its Limited Use requirements. Data obtained through extension permissions is used only to provide or improve Yamora's disclosed, user-facing dating functionality and to maintain its security and reliability.

13. Changes

This policy may be updated when Yamora's practices or legal obligations change. Material changes will be disclosed before they take effect, and renewed consent will be requested where required. The effective date at the top of this page will be updated.

This policy describes Yamora version 0.15.2. Optional service descriptions apply only when those services are configured and enabled in the distributed build.
